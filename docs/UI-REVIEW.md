# UI 评审（Codex）

> 评审对象：`hamster-snack-factory`，竖屏 390×844 像素风（微信小游戏 / 网页版）
> 评审素材：`tools/ui-review/01-title.png` … `15-battle.png`（真机尺寸，共 15 张）
> 评审方式：本机 Codex CLI 分 5 批挂图评审，原始输出留在 `tools/_ui_review_raw/out1…out5.txt`，提示词同目录 `p1…p5*.txt`
> 逐条结论已与源码核对（`tools/shop.js` / `tools/rpg.js` / `tools/adapter.js`），像素尺寸与字号均取自实际绘制常量，不是目测。

---

## 一、总体印象

1. **像素视觉体系是稳的，问题几乎全在"字号/灰阶"与"触控热区"两层。** 15 屏里没有一屏是"布局歪了"，但大量次要文字降到 7–9px、颜色压到 `#5b5374` / `#6a6480`（暗紫底上几乎隐形），同时页签/切页钮高度只有 22–28px（低于 44px 目标）。这两件事合起来，让"能看懂"和"点得到"变成新手的主要摩擦。
2. **信息层级在"该突出的没突出"上失分，而不是信息不够。** 队伍页分不清哪只该换；图鉴 20 格看不出收集进度与未解锁；战斗页有关卡名却没有波次数字，血条 14px 细条。玩家要自己算的东西太多。
3. **空状态与"下一步"交代不足是跨屏通病。** 抽奖"本次结果"是一个空盒子、仓鼠盒 2 只配 3×3 网格、组装页预览压在卡片上、详情转职证页写着"已经满阶"却不说这些证该给谁用——这些位置本来是引导的最佳落点，现在都是空白或者一句灰字。

## 四、不建议改的地方（避免瞎折腾）

1. **不要动像素字体与 1px 硬描边，也不要为了"字小"改成矢量字体。** Fusion Pixel 12px + 整数倍缩放是这套 UI 的质地来源。字号问题按"整数 px 往上提一档"解决（8→9、9→10），不要引入 9.5px / 1.5px 描边，那会在真机上糊成灰边。
2. **不要动主色 `#e8843e` / `#fae8c8` 去解决对比度。** 现在读不清的是灰阶（`#5b5374` / `#6a6480`），把灰阶提亮即可；改主色会让 15 屏的按钮、描边、进度条全部重调。
3. **不要改 64×64 精灵 1:1 绘制与敌方灰毛红眼。** 战场可读性主要靠"我方暖色 / 敌方灰红"的色相分离，放大或换色都会打破识别。
4. **不要动竖屏 390×844 与安全区避让。** 15 张截图里没有一屏被安全区切到，说明这块是对的。
5. **不要为了"信息少"把详情页四个页签合回一屏。** 历史 commit 里明确记录过合并会被裁掉且不能下拉；现在的问题是页签太矮，不是拆页太多。
6. **不要把图鉴 20 格改成列表。** 4 列 × 5 行正是为了让玩家横向对比同阶、纵向对比同职业；改成列表会失去这个用途。要补的是"已收集/未解锁"状态。
7. **不要改商店 46px 行高与详情底部 40–46px 按钮。** 这些已接近/达到 44px 目标，真正不达标的是页签（26）、切页钮（22）、返回（24）、洗练（20）、道具键（32）—— 按第 2 章清单逐个补，别整体放大。
8. **不要动 `tools/ui-review/` 的截图与 `assets/`。** 评审用的是真机尺寸定稿图，重截会破坏与本文的对应关系；本次评审未改任何代码与素材。
